# 舵机 PWM 投喂改造设计

## 目标

在保持现有 App / 云端命令接口兼容的前提下，将设备端 `GPIO4` 从简单高低电平输出改为标准 RC 舵机 PWM 输出，实现“转到目标角度后停留一小段时间再回位”的非阻塞投喂动作。

## 方案选择

### 备选方案

1. 原生 `LEDC` + 非阻塞三阶段动作。
2. 引入第三方舵机库后直接写角度。
3. 使用阻塞式 `delay` 顺序执行开门、停留、回位。

### 采用方案

采用方案 1：原生 `LEDC` + 非阻塞三阶段动作。

采用原因：
- 与当前 `loop()` 轮询架构最匹配；
- 不引入新的外部依赖；
- 可以保持联网、采样、回执和互锁逻辑不中断；
- 更容易拆出纯逻辑单测。

## 行为设计

### 投喂动作阶段

单次投喂动作拆成三个阶段：
1. 舵机写入“打开角度”；
2. 在打开角度停留一段时间；
3. 舵机写入“关闭角度”并结束动作。

### 兼容口径

- 保持 `feed_target_g`、`feed_max_run_ms`、`feed_once`、`control/actuate` 现有协议不变。
- `feed_target_g` 不再映射为简单总拉高时长，而是映射为“舵机停留时长”。
- `servo_active` 字段语义保持不变：只要投喂三阶段任一阶段未结束，就维持为 `true`。

### 标定默认值

- 关闭角度：`0°`
- 打开角度：`70°`
- 最短停留时长：`300ms`
- 线性增量：每 `10g` 增加 `120ms`
- 最大停留时长：`1500ms`
- PWM 频率：`50Hz`
- 脉宽范围：`500us ~ 2400us`

## 实现边界

- 本轮仅改设备端固件与相关测试、文档。
- 不新增 App 配置项。
- 不引入多舵机、多档位校准页面。
- 不在本轮实现机械结构校准向导。

## 状态与超时

- `StartFeed()` 启动后只登记动作状态，不阻塞。
- `Loop()` 按 `now_ms` 推进阶段。
- 若整次动作预算超过 `feed_max_run_ms`，仍按现有语义记为超时失败。
- 水泵与投喂互锁逻辑保持不变。

## 测试策略

优先把可测试逻辑从硬件输出里拆出来：
- `feed_target_g -> hold_ms` 的映射函数；
- 投喂阶段推进逻辑；
- 超时判定与完成判定。

在 `native` 测试环境新增 `actuator_manager` 相关测试，使用 `PIO_UNIT_TESTING` 下的轻量硬件抽象屏蔽 `Arduino` 舵机底层输出。
