# 全量审计问题修复计划

- 计划文件：`docs/Plan/202602211203_全量审计问题修复计划.md`
- 生成时间：2026-02-21 12:03
- 目标：修复当前审计中确认的端云链路、交互闭环与编译验证问题，达到“可编译、可烧录、可联调”的课设交付状态。

## 1. 修复范围

### 1.1 设备侧（PetHome_Device）
1. 修复本地设置模式“可选项不可进入编辑态”的逻辑断点。
2. 将关键上报时间戳统一为 Unix 毫秒语义（优先 NTP 时间，失败回退 `millis()`）。
3. 维持投喂/补水/互锁/告警现有闭环不回退。
4. 修复 `pio test` 依赖异常，确保至少可完成测试构建阶段。

### 1.2 应用侧（PetHome_APP）
1. 修复 IoTDA 签名中 URI 与 Query 的规范化问题。
2. 修复命令回执默认“成功”误判，明确“已受理待回执”与真实结果区分。
3. 将构建目标 SDK 收敛到 API 17 口径。
4. 保持设备列表、历史曲线、日报功能不回退。

### 1.3 文档侧（docs）
1. 同步 `Interface.MD` 中 AP `/status` 示例与设备实现一致（`ap_pwd`）。
2. 记录当前云参数联通风险与联调前置动作。

## 2. 实施顺序

1. 设备侧修复（设置态 + 时间戳 + 单测依赖）。
2. 应用侧修复（签名 + 回执判定 + API17 目标）。
3. 文档对齐。
4. 执行验证命令并输出结果。

## 3. 验证门禁

1. `python scripts/code_guard.py`
2. `python -m platformio run -d PetHome_Device -e esp32s3 -t clean`
3. `python -m platformio run -d PetHome_Device -e esp32s3`
4. `python -m platformio test -d PetHome_Device -e esp32s3 --without-uploading --without-testing`

## 4. 完成判定

1. 设备端编译通过，测试构建阶段通过。
2. App 关键签名与命令判定逻辑完成修复。
3. 本地设置参数可进入编辑并确认保存。
4. 文档口径与代码行为一致。

## 5. 执行结果（2026-02-21）

### 5.1 已完成

1. 设备侧设置页长按 2 秒交互修复：先进入编辑态，再确认保存。
2. 设备侧 `ts` 统一改为 Unix ms（优先 NTP 时间，失败回退 `millis()`）。
3. 设备侧 MQTT 鉴权改为 IoTDA 设备密钥规范：
   - `client_id={device_id}_0_0_{yyyyMMddHH}`
   - `password=HMAC-SHA256(key=yyyyMMddHH, message=device_secret)`
4. App 侧签名 canonical 口径修复（URI 与 Query 分离）。
5. App 侧签名算法切换为 `V11-HMAC-SHA256` 并加入 `Instance-Id` 请求头。
6. App 侧命令“已受理待回执”与真实执行回执语义拆分。
7. App 侧设备绑定改为先校验云端设备存在性再写本地。
8. App 侧配置输入框回填补齐（温湿阈值）。
9. API 口径锁定为 17（`targetSdkVersion=5.0.5(17)`）。
10. Interface/TECH/Acceptance/HuaweiCloud 文档与实现对齐。
