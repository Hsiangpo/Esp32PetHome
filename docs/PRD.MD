# 基于ESP32的智能宠物屋系统 - 产品需求文档（PRD）

- 文档版本：v0.3
- 更新日期：2026-02-20
- 目标读者：固件 / 云端 / App / 测试

> 说明：本PRD目标是“可开发 + 可联调 + 可验收”，作为单人课设项目，文档中所述功能即为全量集合，项目将采取一次性完整开发闭环。

## 1. 项目概述

本系统基于ESP32-S3开发板，实现智能宠物屋的自动化管理。系统负责多传感器数据采集、执行器控制，以及与华为云IoTDA平台的稳定连接和策略下发。用户可通过鸿蒙App远程监控和控制设备。

### 1.1 目标与范围（功能全集）

- 目标：稳定采集环境/粮水状态并上云；提供本地自动控制与远程手动控制；支持阈值/投喂量配置；支持历史曲线与基础告警。
- 范围：
  - 设备端：传感器采集、OLED本地显示、按键交互、自动控制闭环、端云通信、离线容错。
  - 云端：设备影子/期望配置、数据入库与查询（为App提供历史曲线接口）、告警事件转发。
  - App端：配网绑定、实时监控、远程控制、参数配置、历史曲线、告警查看。

### 1.2 超出课设范围（本项目不包含）

- 摄像头视频、语音交互
- 多设备联动（跨家庭/跨账号共享策略）
- AI宠物行为分析

### 1.3 目标用户与典型场景

| 用户角色 | 特征 | 核心诉求 |
| -------- | ---- | -------- |
| 上班族宠物主人（主用户） | 白天不在家，依赖远程监控 | 粮水状态可见、异常可感知、远程可干预 |
| 家庭成员（次用户） | 偶尔查看设备状态 | 简单易用、误操作风险低 |
| 运维/售后（内部） | 处理故障与升级 | 能快速定位故障、可远程下发配置 |

典型场景：

- 工作日白天：依靠自动投喂/补水维持基础照护。
- 夜间：按光照和夜间模式自动控制照明。
- 短期出差（1~3天）：通过App查看历史曲线与告警，必要时远程手动控制。

### 1.4 成功指标（业务+产品）

| 指标 | 目标值 | 统计口径 |
| ---- | ------------- | -------- |
| 自动投喂成功率 | >= 98% | `feed_once`触发次数中成功完成的比例（按天统计） |
| 自动补水成功率 | >= 98% | 补水流程触发次数中在超时前恢复`OK`的比例 |
| 数据完整率 | >= 99% | 设备在线时，应上报点位中成功入库的比例 |
| 远程命令成功率 | >= 97% | App下发命令中执行成功比例（排除互锁拒绝） |
| 告警时效 | <= 120s | 条件成立到App可见告警的延迟P95 |

## 2. 硬件架构

### 2.1 主控制器

- **型号**：ESP32-S3开发板
- **职责**：传感器数据采集、执行器控制、Wi-Fi联网、云平台通信

### 2.2 供电方案

- **供电方式**：DC直流供电（5V USB）
- **供电设备**：充电宝或USB电源适配器
- **推荐规格**：5V / 2A及以上（舵机/水泵启动电流较大）
- **约束**：高功耗执行器（舵机、水泵）默认不允许并发运行，避免欠压复位（详见6.2互锁策略）。

## 3. 传感器模块

| 传感器         | 型号/规格           | 功能                                                      |
| -------------- | ------------------- | --------------------------------------------------------- |
| 温湿度传感器   | Sensirion SHT31-DIS | 监测环境温度和湿度                                        |
| 空气质量传感器 | SGP30               | 监测空气质量（VOC相关指标）。设备端统一上报`voc_index(0~500)`，并上报原始`tvoc_ppb` |
| 称重模块       | HX711 + 压力传感器  | 监测粮食余量（单位：克）                                  |
| 液位传感器     | XKC-Y25（非接触式） | 监测水位状态（点位：LOW/OK）。无需做复杂的水位精度百分比运算。 |
| 光照传感器     | （推荐）BH1750      | 监测环境光照强度（lux）。若替换型号，需确保可换算lux       |
| 按键           | -                   | 本地交互输入                                              |

### 3.1 采集与校准要求

- 温湿度：采样周期默认1s；上报取滑动平均（默认10s窗口）。
- 称重：提供基础“空载去皮 + 系数校正”流程；重量用于余量告警与显示，不作为投喂闭环控制（详见6.2.1）。
- 空气质量：
  - 使用SGP30：读取`TVOC(ppb)`并映射到`voc_index`（映射规则见10.1，联调后可调整）。
- 液位：XKC-Y25输出为点位状态；需要在硬件安装时确定“LOW触发高度”。

## 4. 执行器模块

| 执行器     | 型号/规格          | 功能                   |
| ---------- | ------------------ | ---------------------- |
| OLED显示屏 | SSD1306            | 本地数据显示与菜单交互 |
| 水泵       | -                  | 自动补水               |
| 舵机       | -                  | 控制出粮阀门           |
| 继电器模块 | 5V单路             | 控制排风扇             |
| LED灯      | GPIO直驱           | 照明                   |

### 4.1 安全互锁与保护（硬件/固件协同）

- 互锁：舵机与水泵默认不允许并发；舵机/水泵运行期间禁止进入深睡。
- 超时：水泵与舵机都必须有最大运行时长保护（防空转/防卡死）。
- 上电默认态：所有执行器上电默认关闭；仅在完成初始化与传感器自检后进入自动模式。

## 5. 通信方案

- **设备接入**：ESP32-S3板载2.4GHz Wi-Fi
- **配网方式**：AP热点配网模式
- **云平台**：华为云IoTDA
  - 设备接入（使用设备ID和密钥进行基础明文认证；作为单人课设，云平台需要的 AK/SK、设备密钥等参数直接硬编码在代码中即可）
  - 设备影子管理（最新状态 + 期望配置）
  - 规则引擎转发数据至时序存储（可选归档到对象存储）
  - 1883 端口纯 MQTT（非MQTTS）协议通信（不启用任何证书校验与应用层加密）

### 5.1 上报与控制时序（必须明确）

- 本地采样频率（用于控制/显示）：默认1s（可配置0.5~5s）。
- 云端上报频率（用于App“实时”与历史）：默认60s。
- 变化触发上报（推荐）：关键字段变化超过阈值则立即上报，但需满足最小间隔（默认5s），避免频繁上报。
- 时间同步：设备联网后通过NTP校时；所有上报带`ts`（Unix ms）。

### 5.2 离线策略（不作要求）

- Wi-Fi/云端断连时：尽可能保持本地基础控制运行。
- **课设简化点：** 不做离线数据缓存和断连续传（网络断开期间的数据直接丢弃，不考虑历史断档补报问题，大幅减轻设备端内存管理负担）。

## 6. 功能需求

### 6.1 数据采集与显示

系统采集以下数据，并在OLED屏幕上显示（默认1s刷新；称重与VOC可用更长窗口平滑）：

- 粮食重量（克）
- 水位状态（LOW/OK）
- 环境温度（℃）
- 环境湿度（%RH）
- 光照强度（lux）
- 空气质量（`voc_index`，0~500；可选显示`tvoc_ppb`）

云端上报与历史落库以60s为主（详见5.1），App“实时监控”以云端最新值为准，不保证秒级刷新。

### 6.2 自动控制逻辑

| 触发条件            | 执行动作                           | 控制方式                   |
| ------------------- | ---------------------------------- | -------------------------- |
| 粮食重量 < `food_low_threshold_g` | 舵机执行一次投喂动作后关闭         | 开环定量投喂（App设置`feed_target_g`） |
| 水位状态 = LOW      | 水泵启动补水                       | 液位传感器反馈自动停止     |
| 光照 < 下限阈值     | LED灯开启                          | 支持夜间模式               |
| VOC > 上限阈值      | 继电器启动排风扇                   | 空气质量恢复正常后自动停止 |

#### 6.2.1 投喂逻辑（课设简化：开环转动）

- **课设简化点：** 摒弃工业级复杂的“重量反馈闭环”。
- 目标：将舵机转动特定角度/时间视为“一次自动投喂”。
- 基本流程：
  - 当`food_g < food_low_threshold_g`持续T秒时，触发一次投喂动作。
  - 控制舵机开启固定角度（或旋转固定时长）后自动关闭，动作总时长不超过`feed_max_run_ms`。
  - 设备必须回执本次投喂结果（`OK`/`REJECTED`/`FAILED`），失败时产生`FEED_FAILED`事件。
  - 称重数据仅用于余量展示与低粮告警，不用于本次动作成败判定。

#### 6.2.2 补水闭环（必须，防空转）

- 目标：水位从LOW恢复到OK；若无法恢复则停止水泵并告警。
- 基本流程：
  - 水位LOW持续超过`water_debounce_ms`才触发补水（去抖）；
  - 启动水泵，直到水位变为OK并保持`water_ok_hold_ms`；
  - 若运行超过`pump_max_run_ms`仍为LOW，立即停止并告警`WATER_REFILL_FAILED`；
  - 补水成功后进入冷却期`pump_cooldown_ms`，避免频繁启停。

#### 6.2.3 排风控制（建议加滞回，避免频繁启停）

- 启动条件：`voc_index >= voc_on_threshold`持续`voc_debounce_ms`。
- 停止条件：`voc_index <= voc_off_threshold`持续`voc_ok_hold_ms`。
- 保护：
  - 最小运行时长`fan_min_on_ms`；
  - 最大连续运行时长`fan_max_on_ms`（超过则告警但可继续运行，策略可配置）。

#### 6.2.4 照明与夜间模式

- LED开启条件（自动模式）：`lux <= light_on_threshold` 且当前处于“夜间模式允许时段”（可选）。
- LED关闭条件：`lux >= light_off_threshold`（滞回）或退出允许时段。
- 夜间模式：App可配置“允许时段”（例如22:00~07:00）或直接开关。

#### 6.2.5 执行器互锁策略（必须，防欠压复位）

- 互锁规则：`pump_on`与`servo_active`不可同时为真；若收到并发命令，按优先级执行并返回拒绝原因。
- 推荐优先级：安全相关停止命令 > 补水停止 > 投喂停止 > 补水启动 > 投喂启动 > 风扇/照明开关。

### 6.3 阈值设置

- **默认值**：系统内置默认阈值（见9章）；阈值需提供“可配置范围”和“恢复默认”能力
- **调节方式**：
  - 本地：通过按键调节
  - 远程：通过App调节
- **说明**：
  - 液位LOW触发高度主要由传感器安装位置决定，软件仅提供去抖/保持时长与超时保护等参数。

### 6.4 本地交互（OLED + 按键）

**显示页面**（多页切换）：

1. **主页**：显示当前粮食重量、水位状态
2. **环境页**：显示温度、湿度、光照
3. **空气页**：显示VOC指数、排风扇状态
4. **设置页**：显示/调节各项阈值

**按键功能**：

| 操作        | 功能                         |
| ----------- | ---------------------------- |
| 单击        | 切换到下一个显示页面         |
| 双击        | 进入/退出设置模式            |
| 长按（2秒） | 在设置模式下确认当前阈值修改 |
| 长按（5秒） | 恢复所有阈值为默认值         |

### 6.5 告警与事件

- 设备需产生并上报以下事件（至少）：
  - `LOW_FOOD`：粮食重量低于下限持续T秒
  - `LOW_WATER`：水位LOW持续T秒（与补水逻辑解耦，上报用于提醒）
  - `WATER_REFILL_FAILED`：补水超时失败
  - `FEED_FAILED`：投喂动作失败（超时/互锁拒绝后执行失败）
  - `SENSOR_FAULT`：传感器读数异常或离线（I2C错误/超量程/读数长时间不变）
  - `WIFI_OFFLINE` / `CLOUD_OFFLINE`：离线状态变化
- 呈现方式：
  - OLED：以图标/文字提示当前告警（可滚动查看最近N条，默认N=10）
  - App：告警列表（通过接口拉取展示）

### 6.6 设备控制架构（课设简化：大轮询结构）

- **课设简化点：** 无需实现复杂的有限状态机（FSM）。
- 固件侧只需在主循环 `loop()` 中，通过多个定时的 `if-else` 条件判断去轮询读取传感器数值。
- 触发阈值则直接控制执行器，不引入 `ERROR` 锁定与人工复位流程。只要状态解除，系统就照常跑。

## 7. 鸿蒙App功能

### 7.1 设备管理

- **AP配网**：App引导用户将设备连接至家庭Wi-Fi
- **设备绑定**：通过华为云IoTDA平台完成设备绑定
- **设备列表**：显示已绑定的设备

### 7.2 实时监控

- 实时显示所有传感器数据：
  - 粮食重量
  - 水位状态（LOW/OK）
  - 温度 / 湿度
  - 光照强度
  - `voc_index`（可选显示`tvoc_ppb`）
- 显示各执行器当前状态（开/关）
- 显示设备在线状态、最后更新时间、固件版本

### 7.3 远程控制

- 手动控制各执行器开关：
  - LED灯
  - 水泵
  - 舵机（手动投喂）
  - 排风扇
- 手动投喂支持选择投放克数（默认使用`feed_target_g`）
- 对高风险执行（补水/投喂）需展示“互锁/超时”约束与执行结果

### 7.4 参数设置

- 设置各项阈值
- 设置单次投喂量（克）
- 设置控制保护参数（建议至少暴露）：
  - `feed_max_run_ms`、`water_debounce_ms`、`water_ok_hold_ms`
  - `pump_max_run_ms`、`pump_cooldown_ms`
  - `voc_debounce_ms`、`voc_ok_hold_ms`、`fan_min_on_ms`、`fan_max_on_ms`

### 7.5 历史数据与报表

- 查看传感器历史曲线图
- **查看报表**：根据历史沉淀与事件生成日报或告警报表，以便留痕与直观分析。
- **数据粒度**：每分钟采集一次
- **数据保留周期**：1个月
- **查询方式**：App通过云端API按时间范围拉取（避免直接从对象存储读原始文件）

### 7.6 设备运维（不作要求）

- **课设简化点：** 不需考虑 OTA 固件升级功能。固件更新统一采用本地 USB 物理烧录即可。

## 8. 云端功能

### 8.1 设备影子

- 存储设备最新状态
- 存储期望配置（阈值、投喂量等）
- 设备上线时同步期望配置

### 8.2 数据存储

- 规则引擎将传感器数据写入“可查询的时序存储”（用于App曲线查询）
- 可选：原始数据归档到对象存储（用于离线分析/对账）
- **落库粒度**：默认60s一条（可配置）
- **保留周期**：1个月（可配置）
- 用途：历史数据查询、日报生成、告警追溯

### 8.3 App直连 IoTDA API（当前口径）

> App 不依赖本地自建后端，直接调用 IoTDA App Endpoint（AK/SK 签名）。

- `GET /v5/iot/{project_id}/devices/{device_id}/shadow`：获取设备影子（reported/desired）
- `GET /v5/iot/{project_id}/devices/{device_id}`：获取设备在线状态与基础信息
- `POST /v5/iot/{project_id}/devices/{device_id}/commands`：下发控制/配置命令
- 历史曲线/日报：当前版本采用 App 本地聚合演示数据；后续可按需接入云侧时序查询接口

### 8.4 设备影子字段映射（建议）

`desired`（云端期望配置）建议包含：

- `food_low_threshold_g`
- `light_on_threshold` / `light_off_threshold`
- `voc_on_threshold` / `voc_off_threshold`
- `feed_target_g`
- `feed_max_run_ms`
- `water_debounce_ms` / `water_ok_hold_ms`
- `pump_max_run_ms` / `pump_cooldown_ms`
- `voc_debounce_ms` / `voc_ok_hold_ms`
- `fan_min_on_ms` / `fan_max_on_ms`
- `night_mode_enabled` / `night_mode_start` / `night_mode_end`
- `config_version`

`reported`（设备上报状态）建议包含：

- 10.1中的实时状态字段（`temp_c`、`food_g`、`water_level_state`等）
- `apply_result`：最近一次配置下发结果
- `applied_config_version`
- `last_seen_ts`

## 9. 参数默认值

### 9.1 阈值默认值

| 参数名 | 默认值 | 可配置范围 | 步进 | 说明 |
| ------ | ------ | ---------- | ---- | ---- |
| `food_low_threshold_g` | 50 | 10~500 | 10 | 低于此值触发自动投喂 |
| `water_low_trigger_state` | `LOW` | 固定枚举 | - | 水位传感器低液位触发状态 |
| `light_on_threshold` | 100 | 10~1000 | 10 | 低于此值开启LED照明 |
| `light_off_threshold` | 150 | 20~1200 | 10 | 高于此值关闭LED（滞回） |
| `voc_on_threshold` | 250 | 50~500 | 10 | 高于此值启动排风扇 |
| `voc_off_threshold` | 200 | 0~450 | 10 | 低于此值停止排风扇（滞回） |
| `temp_high_threshold_c` | 30 | 20~40 | 1 | 温度高阈值监测预警 |
| `temp_low_threshold_c` | 10 | 0~20 | 1 | 温度低阈值监测预警 |
| `hum_high_threshold_rh` | 70 | 40~90 | 1 | 湿度高阈值监测预警 |
| `hum_low_threshold_rh` | 30 | 10~60 | 1 | 湿度低阈值监测预警 |

### 9.2 投喂参数

| 参数名 | 默认值 | 可配置范围 | 步进 | 说明 |
| ------ | ------ | ---------- | ---- | ---- |
| `feed_target_g` | 50 | 10~150 | 5 | 单次投喂目标量（用于开环动作配置） |

### 10.1 属性（Telemetry/State）

**字段命名约定**

- `snake_case`；单位明确（如`temp_c`、`hum_rh`、`food_g`）。

| `lux` | float | lux | 光照 |
| `food_g` | float | g | 粮食重量（去皮后） |

  - `voc_index = clamp(round(tvoc_ppb / 2), 0, 500)`（示例，需在联调时根据实际气味与环境校准）

## 11. 非功能需求与验收标准（DoD）

### 11.1 关键指标（演示级要求）

- **课设简化点：** 项目目标是“跑通系统链路、满足演示效果”，无需按照商用量产产品标准验收。
- 建议进行 2~4 小时演示级稳定性测试（能正常展示答辩流程不崩即可），不要求 24 小时无故障拷机。
- 数据与传感器精度无需严苛标定（不必搞法码去皮校准，直接读原始数据乘个系数、数值有合理变化即算过关）。不用追求 ±0.5℃ 和 ±5g 的绝对物理精准度。

### 11.2 行为验收（示例）

- 自动投喂：
  - 当`food_g < food_low_threshold_g`持续T秒，触发投喂流程；
  - 投喂动作需在`feed_max_run_ms`内完成并返回回执`OK`；
  - 若动作超时或因互锁无法执行，必须返回`FAILED/REJECTED`并产生`FEED_FAILED`事件，App可见。
- 自动补水：
  - `water_level_state=LOW`持续T秒触发补水；
  - 成功则在`pump_max_run_ms`内恢复到OK并停止；
  - 失败则停止并产生`WATER_REFILL_FAILED`事件，且不再自动重启水泵（需人工介入）。

### 11.3 安全与隐私（不作要求）

- **课设说明：** 本系统为单人的课设演示项目，**无需考虑通信安全与数据防篡改**。
- 设备到云采用 1883 端口纯 MQTT 直连通信（课设口径不启用 TLS）；App 到 IoTDA REST 采用 AK/SK 请求签名（`SDK-HMAC-SHA256`）。
- 所有华为云平台需要的参数（如 AK/SK、设备密钥、三元组等），直接硬编码（Hardcode）写死在固件和 App 侧代码中即可。App 侧与服务端的权限校验一律从简，优先保证功能通跑。

## 13. 风险与缓解

| 风险 | 概率 | 影响 | 缓解策略 |
| ---- | ---- | ---- | -------- |
| 舵机执行异常导致投喂失败 | 中 | 高 | `feed_max_run_ms`超时保护+回执失败+`FEED_FAILED`事件 |
| 水泵空转或补水无效 | 中 | 高 | `pump_max_run_ms`超时保护+失败告警+人工复位 |
| 供电不足引发复位 | 中 | 高 | 5V/2A+互锁避免并发+上电默认全关 |
| VOC指标跨传感器不一致 | 中 | 中 | 统一`voc_index`定义+映射规则+联调校准 |
| 离线导致数据断档 | 中 | 中 | 明确不补报+App显示“最后更新时间” |

## 14. 冻结决策（已定稿）

- 空气质量传感器选型：`SGP30`，统一上报`tvoc_ppb`并映射`voc_index`。
- 告警通道：仅提供 App 内告警列表查询与展示，不包含系统级推送。
- 历史数据存储：采用时序存储承载查询，对象存储仅作可选归档。
