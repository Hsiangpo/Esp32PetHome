# 基于ESP32的智能宠物屋系统 - 产品需求文档（PRD）

- 文档版本：v0.2
- 更新日期：2026-02-09
- 目标读者：固件 / 云端 / App / 测试

> 说明：本PRD目标是“可开发 + 可联调 + 可验收”。文档中标注“可选/扩展”的能力不作为MVP强制项。

## 1. 项目概述

本系统基于ESP32-S3开发板，实现智能宠物屋的自动化管理。系统负责多传感器数据采集、执行器控制，以及与华为云IoTDA平台的稳定连接和策略下发。用户可通过鸿蒙App远程监控和控制设备。

### 1.1 目标与范围（MVP）

- 目标：稳定采集环境/粮水状态并上云；提供本地自动控制与远程手动控制；支持阈值/投喂量配置；支持历史曲线与基础告警。
- 范围：
  - 设备端：传感器采集、OLED本地显示、按键交互、自动控制闭环、端云通信、离线容错。
  - 云端：设备影子/期望配置、数据入库与查询（为App提供历史曲线接口）、告警事件转发。
  - App端：配网绑定、实时监控、远程控制、参数配置、历史曲线、告警查看。

### 1.2 非目标（本期不做）

- 摄像头视频、语音交互
- 多设备联动（跨家庭/跨账号共享策略）
- AI宠物行为分析

### 1.3 目标用户与典型场景

| 用户角色 | 特征 | 核心诉求 |
| -------- | ---- | -------- |
| 上班族宠物主人（主用户） | 白天不在家，依赖远程监控 | 粮水状态可见、异常可感知、远程可干预 |
| 家庭成员（次用户） | 偶尔查看设备状态 | 简单易用、误操作风险低 |
| 运维/售后（内部） | 处理故障与升级 | 能快速定位故障、可远程下发配置 |

典型场景：

- 工作日白天：依靠自动投喂/补水维持基础照护。
- 夜间：按光照和夜间模式自动控制照明。
- 短期出差（1~3天）：通过App查看历史曲线与告警，必要时远程手动控制。

### 1.4 成功指标（业务+产品）

| 指标 | 目标值（MVP） | 统计口径 |
| ---- | ------------- | -------- |
| 自动投喂成功率 | >= 98% | `feed_once`触发次数中成功完成的比例（按天统计） |
| 自动补水成功率 | >= 98% | 补水流程触发次数中在超时前恢复`OK`的比例 |
| 数据完整率 | >= 99% | 设备在线时，应上报点位中成功入库的比例 |
| 远程命令成功率 | >= 97% | App下发命令中执行成功比例（排除互锁拒绝） |
| 告警时效 | <= 120s | 条件成立到App可见告警的延迟P95 |

## 2. 硬件架构

### 2.1 主控制器

- **型号**：ESP32-S3开发板
- **职责**：传感器数据采集、执行器控制、Wi-Fi联网、云平台通信

### 2.2 供电方案

- **供电方式**：DC直流供电（5V USB）
- **供电设备**：充电宝或USB电源适配器
- **推荐规格**：5V / 2A及以上（舵机/水泵启动电流较大）
- **约束**：高功耗执行器（舵机、水泵）默认不允许并发运行，避免欠压复位（详见6.2互锁策略）。

## 3. 传感器模块

| 传感器         | 型号/规格           | 功能                                                      |
| -------------- | ------------------- | --------------------------------------------------------- |
| 温湿度传感器   | Sensirion SHT31-DIS | 监测环境温度和湿度                                        |
| 空气质量传感器 | BME680 或 SGP30     | 监测空气质量（VOC相关指标）。设备端统一上报`voc_index(0~500)`；可选同时上报原始`tvoc_ppb` |
| 称重模块       | HX711 + 压力传感器  | 监测粮食余量（单位：克）                                  |
| 液位传感器     | XKC-Y25（非接触式） | 监测水位状态（点位：LOW/OK）。水位“百分比”不作为MVP强制项 |
| 光照传感器     | （推荐）BH1750      | 监测环境光照强度（lux）。若替换型号，需确保可换算lux       |
| 按键           | -                   | 本地交互输入                                              |

### 3.1 采集与校准要求

- 温湿度：采样周期默认1s；上报取滑动平均（默认10s窗口）。
- 称重：必须提供“空载去皮 + 标定砝码”流程；重量用于投喂闭环与余量告警（详见6.2）。
- 空气质量：
  - 若使用BME680：建议使用BSEC算法输出IAQ（常见范围0~500）作为`voc_index`。
  - 若使用SGP30：读取`TVOC(ppb)`并映射到`voc_index`（映射规则见10.1，后续可调整）。
- 液位：XKC-Y25输出为点位状态；需要在硬件安装时确定“LOW触发高度”。

## 4. 执行器模块

| 执行器     | 型号/规格          | 功能                   |
| ---------- | ------------------ | ---------------------- |
| OLED显示屏 | SSD1306            | 本地数据显示与菜单交互 |
| 水泵       | -                  | 自动补水               |
| 舵机       | -                  | 控制出粮阀门           |
| 继电器模块 | 5V单路             | 控制排风扇             |
| LED灯      | GPIO直驱           | 照明                   |
| 排风扇     | 小型（继电器控制） | 通风换气               |

### 4.1 安全互锁与保护（硬件/固件协同）

- 互锁：舵机与水泵默认不允许并发；舵机/水泵运行期间禁止进入深睡。
- 超时：水泵与舵机都必须有最大运行时长保护（防空转/防卡死）。
- 上电默认态：所有执行器上电默认关闭；仅在完成初始化与传感器自检后进入自动模式。

## 5. 通信方案

- **设备接入**：ESP32-S3板载2.4GHz Wi-Fi
- **配网方式**：AP热点配网模式
- **云平台**：华为云IoTDA
  - 设备接入与认证
  - 设备影子管理（最新状态 + 期望配置）
  - 规则引擎转发数据至对象存储
  - 启用加密与证书校验

### 5.1 上报与控制时序（必须明确）

- 本地采样频率（用于控制/显示）：默认1s（可配置0.5~5s）。
- 云端上报频率（用于App“实时”与历史）：默认60s。
- 变化触发上报（推荐）：关键字段变化超过阈值则立即上报，但需满足最小间隔（默认5s），避免频繁上报。
- 时间同步：设备联网后通过NTP校时；所有上报带`ts`（Unix ms）。

### 5.2 离线策略

- Wi-Fi/云端断连时：本地自动控制继续运行（使用最近一次生效配置）；本地可手动触发投喂/补水（可选）。
- 断连期间：缓存最近N条上报（默认N=60，约1小时），恢复连接后补报（可选，避免历史断档）。

## 6. 功能需求

### 6.1 数据采集与显示

系统采集以下数据，并在OLED屏幕上显示（默认1s刷新；称重与VOC可用更长窗口平滑）：

- 粮食重量（克）
- 水位状态（LOW/OK）
- 环境温度（℃）
- 环境湿度（%RH）
- 光照强度（lux）
- 空气质量（`voc_index`，0~500；可选显示`tvoc_ppb`）

云端上报与历史落库以60s为主（详见5.1），App“实时监控”以云端最新值为准，不保证秒级刷新。

### 6.2 自动控制逻辑

| 触发条件            | 执行动作                           | 控制方式                   |
| ------------------- | ---------------------------------- | -------------------------- |
| 粮食重量 < 下限阈值 | 舵机开启出粮阀，投放设定克数后关闭 | 定量投喂（APP设置投放量）  |
| 水位状态 = LOW      | 水泵启动补水                       | 液位传感器反馈自动停止     |
| 光照 < 下限阈值     | LED灯开启                          | 支持夜间模式               |
| VOC > 上限阈值      | 继电器启动排风扇                   | 空气质量恢复正常后自动停止 |

#### 6.2.1 投喂闭环（必须，避免“转一转就算投喂”）

- 目标：按配置的`feed_target_g`尽量接近投放，允许少量误差。
- 基本流程：
  - 记录投喂前重量`w0`（去皮后）；
  - 舵机按“开阀-关阀”脉冲方式出粮（避免长时间卡粮），每次脉冲后等待重量稳定；
  - 当`(w_now - w0) >= feed_target_g - feed_tolerance_g`则结束；
  - 若超过`feed_target_g + feed_overshoot_g`视为“超投”（允许但需记录事件）；
  - 超时仍未达到目标则判定失败并告警。
- 失败与卡粮判断：
  - 连续K次脉冲后重量增量小于`min_feed_delta_g`，判定疑似卡粮，最多重试`feed_retry`次；
  - 失败后进入`ERROR`状态，禁止继续自动投喂，需App/本地人工确认复位。

#### 6.2.2 补水闭环（必须，防空转）

- 目标：水位从LOW恢复到OK；若无法恢复则停止水泵并告警。
- 基本流程：
  - 水位LOW持续超过`water_debounce_ms`才触发补水（去抖）；
  - 启动水泵，直到水位变为OK并保持`water_ok_hold_ms`；
  - 若运行超过`pump_max_run_ms`仍为LOW，立即停止并告警`WATER_REFILL_FAILED`；
  - 补水成功后进入冷却期`pump_cooldown_ms`，避免频繁启停。

#### 6.2.3 排风控制（建议加滞回，避免频繁启停）

- 启动条件：`voc_index >= voc_on_threshold`持续`voc_debounce_ms`。
- 停止条件：`voc_index <= voc_off_threshold`持续`voc_ok_hold_ms`。
- 保护：
  - 最小运行时长`fan_min_on_ms`；
  - 最大连续运行时长`fan_max_on_ms`（超过则告警但可继续运行，策略可配置）。

#### 6.2.4 照明与夜间模式

- LED开启条件（自动模式）：`lux <= light_on_threshold` 且当前处于“夜间模式允许时段”（可选）。
- LED关闭条件：`lux >= light_off_threshold`（滞回）或退出允许时段。
- 夜间模式（MVP）：App可配置“允许时段”（例如22:00~07:00）或直接开关。

#### 6.2.5 执行器互锁策略（必须，防欠压复位）

- 互锁规则：`pump_on`与`servo_active`不可同时为真；若收到并发命令，按优先级执行并返回拒绝原因。
- 推荐优先级：安全相关停止命令 > 补水停止 > 投喂停止 > 补水启动 > 投喂启动 > 风扇/照明开关。

### 6.3 阈值设置

- **默认值**：系统内置默认阈值（见9章）；阈值需提供“可配置范围”和“恢复默认”能力
- **调节方式**：
  - 本地：通过按键调节
  - 远程：通过App调节
- **说明**：
  - 液位LOW触发高度主要由传感器安装位置决定，软件仅提供去抖/保持时长与超时保护等参数。

### 6.4 本地交互（OLED + 按键）

**显示页面**（多页切换）：

1. **主页**：显示当前粮食重量、水位状态
2. **环境页**：显示温度、湿度、光照
3. **空气页**：显示VOC指数、排风扇状态
4. **设置页**：显示/调节各项阈值

**按键功能**：

| 操作        | 功能                         |
| ----------- | ---------------------------- |
| 单击        | 切换到下一个显示页面         |
| 双击        | 进入/退出设置模式            |
| 长按（2秒） | 在设置模式下确认当前阈值修改 |
| 长按（5秒） | 恢复所有阈值为默认值         |

### 6.5 告警与事件（MVP必须）

- 设备需产生并上报以下事件（至少）：
  - `LOW_FOOD`：粮食重量低于下限持续T秒
  - `LOW_WATER`：水位LOW持续T秒（与补水逻辑解耦，上报用于提醒）
  - `WATER_REFILL_FAILED`：补水超时失败
  - `FEED_FAILED`：投喂失败（疑似卡粮/超时）
  - `SENSOR_FAULT`：传感器读数异常或离线（I2C错误/超量程/读数长时间不变）
  - `WIFI_OFFLINE` / `CLOUD_OFFLINE`：离线状态变化
- 呈现方式：
  - OLED：以图标/文字提示当前告警（可滚动查看最近N条，默认N=10）
  - App：告警列表；可选推送通知（后续增强）

### 6.6 设备运行状态机（建议实现）

状态定义：

- `BOOTING`：上电初始化与自检
- `IDLE`：在线/离线均可进入的空闲监控态
- `AUTO_CONTROL`：自动控制执行中（投喂/补水/排风/照明）
- `MANUAL_CONTROL`：远程或本地手动控制执行中
- `ERROR`：关键流程失败（如`FEED_FAILED`/`WATER_REFILL_FAILED`）后的保护态
- `UPGRADING`：OTA升级中（可选）

关键迁移：

- `BOOTING -> IDLE`：初始化与自检通过
- `IDLE -> AUTO_CONTROL`：满足自动触发条件
- `IDLE -> MANUAL_CONTROL`：收到合法手动命令
- `AUTO_CONTROL -> ERROR`：达到失败条件（超时/卡粮/传感器故障）
- `ERROR -> IDLE`：收到`reset_error`且安全条件满足
- 任意态 -> `BOOTING`：设备重启
- `IDLE -> UPGRADING -> BOOTING`：执行OTA（可选）

## 7. 鸿蒙App功能

### 7.1 设备管理

- **AP配网**：App引导用户将设备连接至家庭Wi-Fi
- **设备绑定**：通过华为云IoTDA平台完成设备绑定
- **设备列表**：显示已绑定的设备

### 7.2 实时监控

- 实时显示所有传感器数据：
  - 粮食重量
  - 水位状态（LOW/OK）
  - 温度 / 湿度
  - 光照强度
  - `voc_index`（可选显示`tvoc_ppb`）
- 显示各执行器当前状态（开/关）
- 显示设备在线状态、最后更新时间、固件版本

### 7.3 远程控制

- 手动控制各执行器开关：
  - LED灯
  - 水泵
  - 舵机（手动投喂）
  - 排风扇
- 手动投喂支持选择投放克数（默认使用`feed_target_g`）
- 对高风险执行（补水/投喂）需展示“互锁/超时”约束与执行结果

### 7.4 参数设置

- 设置各项阈值
- 设置单次投喂量（克）
- 设置控制保护参数（建议至少暴露）：
  - `pump_max_run_ms`、`feed_max_run_ms`、`fan_min_on_ms`

### 7.5 历史数据

- 查看传感器历史曲线图
- **数据粒度**：每分钟采集一次
- **数据保留周期**：1个月
- **查询方式**：App通过云端API按时间范围拉取（避免直接从对象存储读原始文件）

### 7.6 设备运维（建议）

- OTA固件升级（可选）：App触发升级，展示升级进度与结果；失败可回滚到上一个稳定版本（如支持双分区）。

## 8. 云端功能

### 8.1 设备影子

- 存储设备最新状态
- 存储期望配置（阈值、投喂量等）
- 设备上线时同步期望配置

### 8.2 数据存储

- 规则引擎将传感器数据写入“可查询的时序存储”（用于App曲线查询）
- 可选：原始数据归档到对象存储（用于离线分析/对账）
- **落库粒度**：默认60s一条（可配置）
- **保留周期**：1个月（可配置）
- 用途：历史数据查询、日报生成、告警追溯

### 8.3 App后端API（MVP必须）

> App不直接读取对象存储文件；由后端提供统一接口，屏蔽存储实现。

- `GET /devices/{id}/latest`：获取最新状态（影子reported + 在线状态）
- `GET /devices/{id}/history?metric=...&from=...&to=...&step=60s`：获取历史曲线
- `GET /devices/{id}/events?from=...&to=...`：获取事件/告警
- `POST /devices/{id}/commands`：下发控制/配置命令并返回`request_id`

### 8.4 设备影子字段映射（建议）

`desired`（云端期望配置）建议包含：

- `food_low_threshold_g`
- `light_on_threshold` / `light_off_threshold`
- `voc_on_threshold` / `voc_off_threshold`
- `feed_target_g`
- `pump_max_run_ms` / `feed_max_run_ms` / `fan_min_on_ms`
- `night_mode_enabled` / `night_mode_start` / `night_mode_end`
- `config_version`

`reported`（设备上报状态）建议包含：

- 10.1中的实时状态字段（`temp_c`、`food_g`、`water_level_state`等）
- `apply_result`：最近一次配置下发结果
- `applied_config_version`
- `last_seen_ts`

## 9. 参数默认值

### 9.1 阈值默认值

| 参数     | 默认值  | 说明                   |
| -------- | ------- | ---------------------- |
| 粮食下限 | 50 克   | 低于此值触发自动投喂   |
| 水位下限 | LOW点位 | 水位传感器LOW触发补水  |
| 光照下限 | 100 lux | 低于此值开启LED照明    |
| VOC上限  | 250     | 高于此值启动排风扇     |
| 温度上限 | 30 ℃    | 高于此值可作为监测预警 |
| 温度下限 | 10 ℃    | 低于此值可作为监测预警 |
| 湿度上限 | 70 %RH  | 高于此值可作为监测预警 |
| 湿度下限 | 30 %RH  | 低于此值可作为监测预警 |

### 9.2 投喂参数

| 参数       | 默认值 |
| ---------- | ------ |
| 单次投喂量 | 50 克  |

### 9.3 保护与滞回默认值（建议）

| 参数                | 默认值 | 说明 |
| ------------------- | ------ | ---- |
| `feed_tolerance_g`  | 5 g    | 达标误差（下限） |
| `feed_overshoot_g`  | 10 g   | 允许超投上限（记录事件但不失败） |
| `feed_max_run_ms`   | 20000  | 投喂最大耗时（含多次脉冲与等待） |
| `feed_retry`        | 2      | 疑似卡粮重试次数 |
| `pump_max_run_ms`   | 30000  | 水泵最大运行时长 |
| `pump_cooldown_ms`  | 60000  | 补水冷却期 |
| `voc_on_threshold`  | 250    | 风扇启动阈值（与`VOC上限`一致） |
| `voc_off_threshold` | 200    | 风扇停止阈值（滞回） |
| `fan_min_on_ms`     | 60000  | 风扇最小开机时长 |
| `light_on_threshold`  | 100  | LED开启阈值 |
| `light_off_threshold` | 150  | LED关闭阈值（滞回） |

## 10. 端云数据模型（属性/事件/命令）

> 目标：固件、云端、App三方对齐字段名与语义，避免“能连上但无法联调”的问题。

### 10.1 属性（Telemetry/State）

**字段命名约定**

- `snake_case`；单位明确（如`temp_c`、`hum_rh`、`food_g`）。
- `ts`统一为Unix毫秒时间戳（设备侧生成，NTP校准）。

| 字段 | 类型 | 单位/枚举 | 说明 |
| ---- | ---- | --------- | ---- |
| `ts` | int64 | ms | 采样时间 |
| `temp_c` | float | ℃ | 温度 |
| `hum_rh` | float | %RH | 湿度 |
| `lux` | float | lux | 光照 |
| `food_g` | float | g | 粮食重量（去皮后） |
| `water_level_state` | string | `LOW`/`OK` | 水位点位状态 |
| `voc_index` | int | 0~500 | VOC归一化指数（0好-500差） |
| `tvoc_ppb` | int | ppb | 可选：原始TVOC（若传感器支持） |
| `fan_on` | bool | - | 排风扇状态 |
| `led_on` | bool | - | LED状态 |
| `pump_on` | bool | - | 水泵状态 |
| `servo_active` | bool | - | 舵机动作中 |
| `online` | bool | - | 云端可计算或设备上报均可（建议由云端计算） |
| `fw_version` | string | - | 固件版本 |
| `last_error` | string | - | 最近一次错误码（可选） |

**`voc_index`说明**

- BME680(BSEC)：直接使用IAQ（常见0~500）。
- SGP30：上报`tvoc_ppb`，并按映射函数生成`voc_index`（MVP采用简单线性/分段映射；后续可改为经验模型）：
  - `voc_index = clamp(round(tvoc_ppb / 2), 0, 500)`（示例，需在联调时根据实际气味与环境校准）

### 10.2 事件（Events/Alarms）

事件字段建议：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `ts` | int64 | 事件发生时间（ms） |
| `event_type` | string | 见6.5枚举 |
| `level` | string | `INFO`/`WARN`/`ERROR` |
| `detail` | object | 事件扩展字段（如`w0/w1/target`、`duration_ms`等） |

### 10.3 命令（Downlink Commands）

命令需包含幂等与回执：

- 请求：`request_id`（UUID/雪花）、`ts`、`cmd`、`params`
- 回执：`request_id`、`result`（`OK`/`REJECTED`/`FAILED`）、`reason`、`ts`

建议命令集（MVP）：

| 命令 | 参数 | 说明 |
| ---- | ---- | ---- |
| `set_config` | `config`对象 | 下发阈值/保护参数；设备持久化并回报生效版本 |
| `actuate` | `led_on?` `fan_on?` `pump_on?` | 手动开关执行器（受互锁/超时保护） |
| `feed_once` | `target_g` | 触发一次投喂（受互锁/卡粮保护） |
| `reset_error` | - | 清除`ERROR`状态并恢复自动模式（需满足安全条件） |

## 11. 非功能需求与验收标准（DoD）

### 11.1 关键指标

- 可靠性：设备连续运行24h无死机；具备看门狗；异常可自恢复或可定位。
- 实时性：
  - 云端最新数据：上报周期60s情况下，App看到的“最新值”延迟 <= 2个周期；
  - 命令下发：网络正常时，命令到执行开始 <= 3s（目标值）。
- 精度（在完成校准后）：
  - 温度误差 <= ±0.5℃；湿度误差 <= ±3%RH（以传感器指标为参考，实际以联调测试为准）。
  - 称重误差：静态误差 <= ±5g（目标值，需标定）。

### 11.2 行为验收（示例）

- 自动投喂：
  - 当`food_g < food_low_threshold`持续T秒，触发投喂流程；
  - 投喂结束后，重量增量满足`target_g - tolerance <= delta <= target_g + overshoot`；
  - 投喂失败必须停止并产生`FEED_FAILED`事件，App可见。
- 自动补水：
  - `water_level_state=LOW`持续T秒触发补水；
  - 成功则在`pump_max_run_ms`内恢复到OK并停止；
  - 失败则停止并产生`WATER_REFILL_FAILED`事件，且不再自动重启水泵（需人工介入）。

### 11.3 安全与隐私（MVP）

- 端云链路必须使用TLS；敏感信息（设备密钥/证书）不得明文存储在可读文件系统中，建议存储于NVS并开启加密（如支持）。
- App侧不展示任何设备密钥；绑定流程需服务端校验权限。

## 13. 风险与缓解

| 风险 | 概率 | 影响 | 缓解策略 |
| ---- | ---- | ---- | -------- |
| 舵机卡粮导致投喂失败 | 中 | 高 | 脉冲出粮+增量检测+重试+失败保护态 |
| 水泵空转或补水无效 | 中 | 高 | `pump_max_run_ms`超时保护+失败告警+人工复位 |
| 供电不足引发复位 | 中 | 高 | 5V/2A+互锁避免并发+上电默认全关 |
| VOC指标跨传感器不一致 | 中 | 中 | 统一`voc_index`定义+映射规则+联调校准 |
| 离线导致数据断档 | 中 | 中 | 本地缓存补报（可选）+App显示“最后更新时间” |
